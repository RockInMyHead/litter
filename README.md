# Производственное планирование

Локальный интерактивный прототип для Мценского литейного завода. Период демонстрации — ноябрь 2026 года.

## Запуск

Требуется Node.js 22.15 или новее. Устанавливать зависимости не нужно.

```sh
npm run dev
```

Откройте http://127.0.0.1:5173. Программа работает без интернета. Состояние демонстрации сохраняется в браузере для этого адреса. Чтобы изменить порт, используйте `npm run dev -- --port 5174`.

```sh
npm test
npm run build
npm run start -- --dist
```

Последние две команды собирают и запускают статическую версию из `dist/`. Для собственного HTTP-сервера используйте `dist/` как корневую папку.

## Пятиминутная демонстрация

1. Нажмите **Запустить демо**. Откройте карточку 1С:ERP и выполните локальный обмен. На карте 11 функциональных блоков, источник заказов и этап утверждения.
2. Перейдите в программу и откройте технологическую карту изделия №3. Проверьте две линии и переключите методику расчёта.
3. Откройте сравнение источников для изделия №3. В книге указаны ВЧ 50 в примере расчёта и ВЧ 40 в спецификации. Для перехода к v2 оставьте решение открытым.
4. Измените заказ изделия №3 с 20 000 до 24 000. Карта покажет передачу пересчитанных данных. Общий заказ составит 24 852 шт., масса заказа — 41,7706 т, расход жидкого металла — 109,8737 т. При исходном демонстрационном остатке дефицит стержней изделия №3 составит 2 244 шт.
5. Сравните v1 и v2. Согласование загрузки АФЛ №2 сохраняется. Откройте решение СГЭ, переключитесь на инженера СГЭ и согласуйте его расчёт.
6. Откройте сводку и проверьте, что мешает утвердить план. После просмотра сводки закройте панель и покажите паспорт программы.

Кнопка **Сбросить демонстрацию** возвращает исходные заказы, нормативы, роли, граф и согласования, очищает журнал и открывает карту.

## Как утвердить демонстрационный план

В роли технолога ОГМет разберите три расхождения в **Контроле качества данных**. Для двух расхождений сплавов выберите доступные ресурсные спецификации. Альтернативный сплав требует соответствующей рецептуры. При дефиците стержней укажите в настройках остаток или поставку до конца периода. Для ОМТО зафиксируйте подтверждение обеспечения по текущей ведомости. После решений ответственных ролей переключитесь на руководителя и нажмите **Утвердить производственную программу**. Последующие изменения создают отдельную рабочую версию.

## Данные и методика

- Из шести листов приложенной книги извлечены пять заказов, 95 операций и 330 строк ресурсов. Коды, номера операций, нормы и номера строк сохранены в `src/data/factory/workbook.ts`. Для повторного извлечения используйте `python3 scripts/import-workbook.py /путь/к/книге.xlsx`.
- Методика Excel использует исходные дробные формы и смены. Производственное округление рассчитывает целые формы, заливку, годный выпуск, расход жидкого металла и стержни.
- Нормы шихты предварительно интерпретируются как кг/т. Повторяющиеся одинаковые строки основной рецептуры учитываются один раз. Строки полуфабрикатов доступны в дереве. Повторное включение зеркальных норм в расчёт шихты исключено. Альтернативную базу можно выбрать в настройках.
- Календарь, переналадки, энергетические и трудовые нормы, срок/приоритет заказов и демонстрационные остатки требуют подтверждения предприятия. Остатки отдельных материалов можно ввести из ведомости. Обмен 1С, и роли моделируются локально, сводка строится по расчётам плана.
- Варианты графика используют известные линии. Совместимость и производительность на альтернативной линии требуют исходных данных. Простой и рост заказов на 20% доступны для просмотра.
- Формулы СГЭ и трудоёмкости редактируются в настройках. Интерпретатор принимает числа, переменные `M` и `K`, скобки и операции `+ - * /`. Редактор карты поддерживает переименование существующих блоков, ответственных, сроки и связи с проверкой циклов.
- Проверки охватывают формулы книги, переход v1 → v2, сохранение независимых согласований, отсутствие подходящей рецептуры, покрытие ресурсов и итоговое утверждение. Browser-проверка проводилась в локальном Chromium-представлении приложения.
